W4·A10 — Two subnets on one wire

Time: 30 min · Needs: one Ethernet switch, one OL9 Router, 2 VPCS · GNS3 project: w04-a10-multinet

The question: A5 gave two subnets two broadcast domains (VLANs) and a router to join them. Here is a stranger arrangement: two subnets on one wire, one broadcast domain, no VLANs at all. Does a router still have anything to do? And is anything actually being routed?

Predict first

  1. PC1 (192.168.10.11) and PC2 (192.168.20.12) are plugged into the same switch, on the same wire. Will PC1 reach PC2 on its own, with no router? ☐ yes ☐ no
  2. If a router is needed even though they share a wire, what does that tell you about how a host decides "local" versus "remote"? _

Build it

One switch, two VPCS, one OL9 router — all on the same switch, one broadcast domain:

PC1 .11 ─┐
PC2 .12 ─┼─[ SW1 ]─ R1 eth0
          │
   one wire, one broadcast domain

Give the two PCs addresses in two different subnets, each pointing at the router:

# PC1 — subnet 192.168.10.0/24
ip 192.168.10.11/24 192.168.10.1

# PC2 — subnet 192.168.20.0/24
ip 192.168.20.12/24 192.168.20.1

Now the unusual part. R1 has one network card, but it needs a foot in both subnets — so give eth0 two addresses, one per subnet, and turn on forwarding:

# on R1
nmcli device set eth0 managed no
ip link set eth0 up

ip addr add 192.168.10.1/24 dev eth0
ip addr add 192.168.20.1/24 dev eth0     # a second address on the same card

sysctl -w net.ipv4.ip_forward=1
ip addr show dev eth0

The second ip addr add is a secondary address — one interface wearing two subnet identities. That is the whole trick.

Do this — it works, and it is routed

From PC1:

ping 192.168.20.12
traceroute 192.168.20.12

What just happened

  • It works — and traceroute shows one hop, 192.168.10.1, the router. Even though PC1 and PC2 are on the same physical wire and could hear each other directly, the traffic detoured through R1. Nothing went straight across.
  • Why the detour? PC1 reads its own netmask, sees 192.168.20.12 is not in 192.168.10.0/24, and therefore treats it as remote — so it does not ARP for PC2 at all. It hands the packet to its gateway (192.168.10.1) instead. PC2 does the mirror image on the way back. The hosts' idea of "local vs remote" is decided entirely by the subnet mask, not by what is physically reachable.
  • This is genuine routing, and ip_forward is what makes it happen. The packet arrives at R1 inside a frame addressed to the router's MAC, but its IP destination is PC2, not the router. With forwarding off, Linux would drop it — "not my address." With forwarding on, R1 looks the destination up, finds 192.168.20.0/24 is directly connected on the same card, re-frames the packet to PC2's MAC, decrements the TTL, and sends it back out the interface it came in on. Turn forwarding off (sysctl -w net.ipv4.ip_forward=0) and the ping stops — proof the router is doing real work, not just sharing a wire.

Do this — the catch: there is no isolation

Start a capture on PC1's link (right-click the link → Start capture). Then, from PC2, make it send a broadcast — the simplest is to clear its ARP and ping its gateway so it has to ARP:

# on PC2
clear ip                # VPCS: forget learned addresses
ping 192.168.20.1

What just happened

  • PC1's cable sees PC2's ARP broadcast, even though the two are in different subnets. There is only one broadcast domain here — the mask separates them at layer 3, but nothing separates them at layer 2. Compare this with A5: there, a capture on one VLAN's cable stayed silent during the other VLAN's traffic. Here it does not.
  • This arrangement has a name — multinetting (two subnets sharing one segment via secondary addresses). It is real, but it is a stopgap, not a design: you meet it when someone ran out of addresses and bolted a second subnet onto an existing wire, or mid-migration. The clean way to put two subnets on shared switch hardware is VLANs (A5), precisely because VLANs give the layer-2 separation multinetting lacks.
  • The missing isolation is not just untidy — it is a security property you have given up. Any host on the wire can hear every other host's broadcasts regardless of subnet, which is exactly the shared medium the network-security activities exploit (see NS·A3 — ARP spoofing and MITM: a single broadcast domain is what lets an attacker sit in the middle). Two subnets that look separate but share a broadcast domain are separate only on paper.
