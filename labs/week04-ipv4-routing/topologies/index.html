A6–A8 add no nodes, but they do change w04-base

  • A6's redirect section adds a second link from R2 to LAN1's switch and repoints R1's route to 192.168.200.0/24 via 192.168.100.2. The activity ends with restore commands. A7 will behave strangely if they are skipped — verify before the next session.
  • A8 part 4 attaches a NAT node to LAN1's switch so PC1 can reach a public address. It costs no RAM, but it needs working egress from the GNS3 host. Test it before class. A8 also has students store PC1's address as an nmcli connection first — a NAT node hands out addresses, and PC1's has only ever been set with ip addr add. That connection persists in the exported project.
  • A6, A7 and A8 all install nft rules and each activity ends with nft flush ruleset. A forgotten rule is the most likely cause of a later activity "not working".

Consider a third export, w04-base-restored.gns3project, taken after A6's restore step — it saves a session when a class leaves the redirect wiring in place.

w04-base is the week's spine — export it

Four OL9 nodes — two OL9 Routers, two OL9 PCs — plus a switch on each LAN, three subnets. It takes a full session to cable and address, and A3 and A4 both depend on it being correct.

Export two states:

Export State For
w04-base-broken.gns3project R1 has the route to LAN2; R2 has no return route A2 part 1 — this is the activity's starting point
w04-base-working.gns3project both routes present recovery, and the starting point for A3 and A4

Handing out the broken one saves a session and loses nothing: the fault is the subject of A2, not something students should have to construct.

Verify before distributing

The nmcli device set ethN managed no lines are ip-level and do not travel in an export — they are runtime state, not configuration. A student importing w04-base still has to run them, or NetworkManager will claim the interfaces on boot and the addressing will evaporate.

Either say so when you hand it out, or configure the export with nmcli connection profiles, which do persist inside the node's disk image. The second is more work and more realistic.

A5 depends on the 8021q module

Confirm modprobe 8021q succeeds on the OL9 image before the session. If it is absent from the image, A5 cannot run and milestone 2's R2 requirement is unbuildable — that is a rebuild-the-image problem, not a lab-day problem, so check it early.
