W5·A1 — The mask is a claim

Time: 35 min · Needs: two OL9 PCs on an Ethernet switch · GNS3 project: w05-a1-mask

The question: you have typed /24 after every address for four weeks. What does the host actually do with it?

Build it

H1 and H2, both OL9 PCs, on an Ethernet switch. nmcli device set eth0 managed no on both.

# H1
ip addr add 192.168.10.11/24 dev eth0 ; ip link set eth0 up
# H2
ip addr add 192.168.10.200/24 dev eth0 ; ip link set eth0 up

Confirm they ping.

Predict first

You will change only H1's mask, from /24 to /25. Nothing else — not its address, not H2, not the cable.

  1. Can H1 still reach H2? ☐ yes ☐ no
  2. Can H2 still reach H1? ☐ yes ☐ no
  3. Are those the same question? ☐ yes ☐ no

Do this — watch the table change with the mask

# on H1
ip route show
ip route get 192.168.10.200

ip addr del 192.168.10.11/24 dev eth0
ip addr add 192.168.10.11/25 dev eth0

ip route show
ip route get 192.168.10.200

What just happened

  • The connected route changed from 192.168.10.0/24 to 192.168.10.0/25. The mask's only direct effect is on the routing table — it decides the size of the one route you get for free.
  • ip route get went from a direct answer to Network is unreachable. 192.168.10.200 is above .127 and therefore outside H1's new claim.
  • So a mask is a claim about which addresses are reachable without help. Change the claim and you change what the host considers to be its neighbours — and nothing else at all. No packet was affected, no interface reset, no negotiation with anyone.
  • H2 was not consulted and does not know. Masks are configured per host, never announced, and never checked for agreement. That is A2's subject.

Do this — the boundary, one address at a time

Still on H1 with /25:

ip route get 192.168.10.126
ip route get 192.168.10.127
ip route get 192.168.10.128
ip route get 192.168.10.129
Address Reachable directly? Why
.126
.127
.128
.129

What just happened

  • The behaviour changes between .127 and .128, and nowhere else. 192.168.10.0/25 covers .0–.127; the next address begins a different subnet.
  • .127 is inside the claim but is the broadcast address of that subnet, and .128 is the network address of the next. A3 measures what those two actually do.
  • The boundary is a property of the number, visible only in binary: /25 means "the first 25 bits must match". .127 is 0111 1111 and .128 is 1000 0000 — the 25th bit is the one that flips. Write out both and confirm.

Do this — restore the claim by widening it

ip addr del 192.168.10.11/25 dev eth0
ip addr add 192.168.10.11/24 dev eth0
ip route get 192.168.10.200
ping -c1 192.168.10.200

What just happened

  • Working again, with no change anywhere except one number on one host.
  • Nothing was ever broken. The link, the switch, both NICs and H2 behaved identically throughout. A subnet is not a thing that exists in the network; it is a shared belief held by the hosts, and the network has no opinion about it whatsoever.
