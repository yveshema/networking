W5·A3 — Boundaries, measured

Time: 40 min · Needs: three OL9 PCs on an Ethernet switch · GNS3 project: w05-a3-boundaries

The question: every subnetting exercise says "subtract two — the network address and the broadcast address". Subtract two what, and what happens if you use them anyway?

Build it

H1 .11, H2 .12, H3 .13 — three OL9 PCs, all in 192.168.10.0/24, on one Ethernet switch. nmcli device set eth0 managed no on each. Confirm they ping.

Then: what do you expect to happen if you assign a host the broadcast address anyway?

Do this — the broadcast address is not a name, it is a behaviour

# on H2 and H3
sysctl -w net.ipv4.icmp_echo_ignore_broadcasts=0

# on H1
ping -b -c1 192.168.10.255

What just happened

  • Two replies to one packet, from two different hosts, reported as DUP!. You met this in W3·A3 as a measurement of the broadcast domain; here it is a measurement of the address.
  • .255 is not owned by anybody. It is a value that every host in the subnet recognises as "also me", which is precisely why nobody can be assigned it — an address that means "everyone" cannot also mean "one particular machine".
  • The rule is not arithmetic, it is behaviour. "Subtract two" is a consequence, not a definition.

Do this — use it anyway

# on H3
ip addr flush dev eth0
ip addr add 192.168.10.255/24 dev eth0
ip addr show eth0

Record whether the command was accepted. Then from H1:

ping -c2 192.168.10.255
ip neigh show

And try the network address:

# on H3
ip addr flush dev eth0
ip addr add 192.168.10.0/24 dev eth0
ip addr show eth0

From H1: ping -c2 192.168.10.0.

What just happened

Record what you observed rather than what you expected — behaviour here varies with the stack, and that variation is itself the finding.

  • Linux is permissive about assigning these addresses; the trouble starts with everything else. The broadcast address is interpreted as a broadcast by every other host on the segment, so replies come from machines you did not address, and the ARP cache fills with contradictions.
  • Nothing enforced the rule. No error, no warning from the switch, no complaint from the other hosts. The convention lives in how the other machines interpret the address, and they will all keep interpreting it that way regardless of what H3 believes.
  • That is why "unusable" is a stronger word than the tooling suggests: you can configure it, and it will fail in ways that look like a hardware fault.

Restore H3: ip addr flush dev eth0; ip addr add 192.168.10.13/24 dev eth0.

Do this — move the boundary and find it again

# on all three hosts — same addresses, narrower mask
ip addr flush dev eth0
ip addr add 192.168.10.11/28 dev eth0      # .12 and .13 on the others
ip route show

Now, from H1, find the edges by measurement:

ip route get 192.168.10.14
ip route get 192.168.10.15
ip route get 192.168.10.16
ping -b -c1 192.168.10.15

What just happened

  • /28 gives 16 addresses and 14 usable. The boundary moved from .255 to .15, and every host agreed instantly because they all did the same arithmetic on the same mask.
  • The broadcast ping to .15 produced DUP! replies — the broadcast address moved with the mask, and nothing was configured to make that happen. It is derived, not stored.
  • ip route get located the edge without any binary arithmetic. Use it to check your arithmetic, never to replace it: on paper you must still be able to say why .16 starts a new subnet.

Do this — the sizes where the rule bends

The /30 you used for every transit link in week 4 gives 4 addresses, 2 usable — 50% waste, on every point-to-point link in the network. Linux supports the fix:

# on H1 and H2 — remove H3 from the switch, or ignore it
ip addr flush dev eth0
ip addr add 10.0.0.0/31 dev eth0        # H1
ip addr add 10.0.0.1/31 dev eth0        # H2
ip link set eth0 up
ip route show
ping -c1 10.0.0.1                       # from H1

What just happened

  • Both addresses are usable. 10.0.0.0 is assigned to a host and works, on a prefix where "the network address" would leave nothing at all.
  • A /31 (RFC 3021) is defined for point-to-point links only, where broadcast is meaningless: there is exactly one other machine, so a frame sent to "everyone" and a frame sent to "the other end" are the same frame. With the concept gone, the reserved addresses are unnecessary.
  • So "subtract two" is a rule with a reason, and where the reason does not apply the rule does not either. Learn the reason; the arithmetic follows from it.
  • A /32 has no network at all — one address, no neighbours. It is used for loopbacks and host routes, and you will meet it again in any routing protocol.
