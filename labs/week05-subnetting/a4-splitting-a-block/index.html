W5·A4 — Splitting a block

Time: 45 min · Needs: one OL9 Router, 4 hosts (VPCS is fine), 4 Ethernet switches · GNS3 project: w05-a4-splitting

The question: you are given one /24 and told to build four separate networks out of it, without asking for more addresses. Do it.

Predict first

You have 192.168.50.0/24 and need four equal subnets.

  1. What prefix length? _
  2. How many addresses per subnet? _ How many usable? _
  3. Write out all four:
# Network First usable Last usable Broadcast
1
2
3
4

Do the arithmetic before building. The build is the check, not the method.

Do this — build what you calculated

R1 is an OL9 Router. Each of its four interfaces is a separate subnet, and each subnet gets its own switch with one host on it:

   PC1 ─── SW1 ─── R1:eth0     192.168.50.1/26
   PC2 ─── SW2 ─── R1:eth1     192.168.50.65/26
   PC3 ─── SW3 ─── R1:eth2     192.168.50.129/26
   PC4 ─── SW4 ─── R1:eth3     192.168.50.193/26

Four switches for four hosts is more than this lab strictly needs. It is what the real thing looks like, though — a subnet is a LAN, and a LAN has a switch in it — so from here on the diagrams match what you would actually build.

# on R1 — use YOUR numbers, not these
for i in eth0 eth1 eth2 eth3; do nmcli device set $i managed no; done
ip addr add 192.168.50.1/26   dev eth0 ; ip link set eth0 up
ip addr add 192.168.50.65/26  dev eth1 ; ip link set eth1 up
ip addr add 192.168.50.129/26 dev eth2 ; ip link set eth2 up
ip addr add 192.168.50.193/26 dev eth3 ; ip link set eth3 up
sysctl -w net.ipv4.ip_forward=1
ip route show

Each host gets an address in its own subnet, with the router's address on that interface as its gateway:

# PC1 (VPCS)
ip 192.168.50.10/26 192.168.50.1
# PC2
ip 192.168.50.70/26 192.168.50.65
# PC3
ip 192.168.50.140/26 192.168.50.129
# PC4
ip 192.168.50.200/26 192.168.50.193

Then, from PC1, ping all three others and the router.

What just happened

  • ip route show holds four connected routes, and you typed none of them. Every one is a restatement of an address-plus-mask you assigned.
  • The arithmetic is checked by the build. An off-by-one in a boundary produces a host that cannot reach its own gateway — an immediate, unambiguous failure, in the same session, with no marker involved.
  • Four subnets came out of one /24 by borrowing 2 bits from the host portion: /24 → /26. Those two bits give exactly four combinations, which is why four subnets and not three or five.
  • The cost is visible: 256 addresses became 4 × 62 = 248 usable. Eight addresses vanished into network and broadcast addresses — two per subnet, and you now have four subnets instead of one. Subnetting always costs addresses, and the finer you cut, the more it costs.

Do this — prove the separation

Capture on PC2's link. From PC1, run a broadcast ping and an ARP:

# on PC1 (or an OL9 host in its place)
ip neigh flush all
ping -c1 192.168.50.70
ping -b -c1 192.168.50.63

What just happened

  • PC2's cable carried the routed unicast only — no ARP from PC1, no broadcast.
  • PC1's broadcast to 192.168.50.63 reached its own subnet and stopped at the router. Routers do not forward broadcasts, and that is a large part of what you bought with the split.
  • Compare with week 3: VLANs split a broadcast domain inside one subnet, at layer 2. Here the split is at layer 3, using different subnets and a router. Two mechanisms, similar effect, different layer — and real networks use both together, which is exactly what W4·A5 built.

Do this — the wrong split

Deliberately mis-size one subnet and watch what it does to a neighbour:

# on R1 — eth1 claims a /25 that overlaps eth2's block
ip addr del 192.168.50.65/26 dev eth1
ip addr add 192.168.50.65/25 dev eth1
ip route show
ip route get 192.168.50.140

What just happened

  • Two connected routes now overlap: 192.168.50.0/25 on eth1 covers addresses that 192.168.50.128/26 on eth2 also claims — check the arithmetic and see exactly which.
  • ip route get 192.168.50.140 reveals the winner. Longest prefix decides (W4·A1), so the more specific /26 still wins for PC3 — but the router now believes part of eth2's range is reachable via eth1, and any address in the overlap that is not covered by a longer prefix is sent to the wrong port.
  • No error was reported at any point. Overlapping subnets are accepted silently and fail selectively, which is why an address plan is a document you check before you configure, not after.

Restore: ip addr del 192.168.50.65/25 dev eth1; ip addr add 192.168.50.65/26 dev eth1.

Your four-subnet table, plus:

Usable addresses per subnet

Route chosen for .140 during the overlap

One sentence: what does subnetting cost, and what does it buy?

If it went wrong

Symptom Cause Fix
A host cannot reach its own gateway address outside its subnet recheck the boundary; ip route get from the host
Everything reachable from everywhere all interfaces still /24 the masks must be /26 on both router and hosts
VPCS rejects the gateway gateway outside the host's subnet ip <addr>/<mask> <gw> — the gateway must be inside
Router pings work, host-to-host does not forwarding off sysctl net.ipv4.ip_forward
Broadcast crosses to another subnet it should not check you are watching a link on a different subnet
