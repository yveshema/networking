W3·A4 — VLANs cut the segment ★

Time: 45 min · Needs: A1's topology (OL9 Switch + 4 VPCS), Wireshark · GNS3 project: w03-a1-mac-table (continue in it)

The question: A3 showed that every broadcast costs every host in the domain. Split the domain without buying a second switch and without changing a single address.

Predict first

Four hosts, one subnet, one switch, all pinging happily. You are about to put ports 0–1 in VLAN 10 and ports 2–3 in VLAN 20, changing no IP address on any host.

  1. Can PC1 (VLAN 10) still ping PC2 (VLAN 10)? ☐ yes ☐ no
  2. Can PC1 still ping PC3 (VLAN 20)? ☐ yes ☐ no
  3. If not — what is wrong with the addressing? _

Do this — the cheap version first, for contrast

Before building it properly, see the same effect on the built-in switch. If you still have a GNS3 Ethernet switch topology from week 2: right-click it → Configure, set ports 0–1 to VLAN 10 and ports 2–3 to VLAN 20, all type access. Ping .12 and then .13 from PC1.

.12 works. .13 fails. Correct behaviour, two mouse clicks, and no way whatsoever to see why. That is why the rest of this activity is on the bridge.

Do this — VLANs on the bridge

# on SW1
ip link set dev br0 type bridge vlan_filtering 1

bridge vlan add dev eth0 vid 10 pvid untagged
bridge vlan add dev eth1 vid 10 pvid untagged
bridge vlan add dev eth2 vid 20 pvid untagged
bridge vlan add dev eth3 vid 20 pvid untagged

# remove the default VLAN 1 membership, or nothing is separated
for i in eth0 eth1 eth2 eth3; do bridge vlan del dev $i vid 1; done

bridge vlan show

Start a capture on PC3's link. From PC1:

clear arp
ping 192.168.10.12
ping 192.168.10.13

Then on SW1:

bridge fdb show br br0 | grep -v permanent

What just happened

  • .12 worked. .13 failed. Same subnet, same mask, same switch, correct addressing on both, and no route needed. Nothing at layer 3 can explain this.
  • PC1's ARP broadcast stopped appearing on PC3's capture. The broadcast domain has been cut in two, which is the whole objective — A3's cost is now paid by two hosts instead of four.
  • Every fdb entry now carries a vlan field. There is no longer one forwarding table; there is one table per VLAN, and a MAC learned in VLAN 10 is invisible to VLAN 20. Two switches, sharing a chassis.
  • The switch defines the segment, not the addressing. That sentence is what the entire week exists to earn, and this is where it is paid.
  • Deleting vid 1 was not optional. Ports stay in the default VLAN otherwise, everything remains mutually reachable, and the activity appears not to work.

Do this — a trunk, and the tag itself

Add a second OL9 Switch SW2 (same build as A1), move PC3 and PC4 onto it, and link SW1:eth4↔SW2:eth4. On both switches:

# member of both VLANs, and tagged — note the absence of 'pvid untagged'
bridge vlan add dev eth4 vid 10
bridge vlan add dev eth4 vid 20
bridge vlan show

Start a capture on the SW1↔SW2 link and ping across it within VLAN 10.

What just happened

  • The frames on the trunk carry an 802.1Q tag — Wireshark shows a 802.1Q Virtual LAN layer between Ethernet and IP, with ID: 10 in it. Expand it and note that it is 4 bytes, inserted into the middle of a header you thought you already knew from week 1.
  • The same frames on the access ports at either end have no tag. The tag exists only between switches, because it exists to answer one question — which VLAN did this arrive in? — that only a switch asks. Hosts neither send nor see it.
  • pvid untagged on an access port means exactly that: frames arriving here belong to this VLAN, and frames leaving here go out with the tag stripped.
  • The maximum frame grew by 4 bytes. Standard Ethernet allows 1518; a tagged frame is 1522. That is a real and recurring source of trouble on equipment that was not told to expect it.

Do this — the question the design leaves open

From PC1 in VLAN 10, try to reach PC3 in VLAN 20 one more time. Then try to think of any configuration on SW1 that would let it through.

What just happened

  • There is none. A bridge cannot move a frame between VLANs, by construction — that would defeat the separation you built it for.
  • Traffic between VLANs must go up to layer 3 and come back down, which means a router, which is week 4. Every real network runs this arrangement, and the phrase for it is "router on a stick".
  • Notice what you have therefore built: a network that is deliberately broken between two groups of hosts, with the repair postponed to another device. That is a design decision, not a fault, and it is the normal state of every campus network you have used.

If it went wrong

Symptom Cause Fix
Everything still reachable vid 1 not removed the for loop deleting vid 1 is mandatory
All pings fail, including within a VLAN ports missing pvid untagged bridge vlan show — access ports must show PVID Egress Untagged
No 802.1Q layer on the trunk capture you captured an access link capture the SW1↔SW2 link specifically
Trunk works one way only one switch's trunk port is missing a VLAN both ends need both vid lines
