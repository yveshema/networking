STP priority

The requirement for steps of 4096 comes down to how a switch creates its Bridge Identifier (ID) when using the standard Extended System ID field.

To understand this, we have to look at the exact binary breakdown of the Bridge Priority field.The 16-Bit Priority Field SplitOriginally, the Spanning Tree Protocol (STP) allocated a full 16-bit binary field purely for the Bridge Priority. This allowed any number from 0 to 65,535.

However, when VLANs (Virtual Local Area Networks) were introduced, switches needed to run a separate instance of STP for each VLAN (Per-VLAN Spanning Tree or PVST). To avoid needing a unique MAC address for every single VLAN instance, the IEEE updated the standard. They split that original 16-bit field into two distinct parts:

  • Bridge Priority (4 bits): The leftmost (most significant) bits.
  • Extended System ID (12 bits): The rightmost bits, used exclusively to hold the VLAN ID.

|===============================================================| | Original 16-bit Field | |===============================================================| | 4-bit Bridge Priority | 12-bit Extended System ID | (Multiples of 4096) (Holds the VLAN ID, 1 to 4094) | |===============================================================|

Why the Math Forces 4096

In binary, the 12 bits reserved for the VLAN ID can represent any number from 0 to 4,095 (2¹² = 4096 total values).Because the 4 priority bits sit to the left of these 12 bits, changing the very lowest priority bit means you are changing the 13th bit of the overall 16-bit number.

In binary place values, the 13th bit represents the number 4096 (2¹²).Therefore, you can only manipulate the four leftmost bits. Your configuration options are limited to the following binary combinations:

  • 0000 (plus VLAN ID) = 0 0001 (plus VLAN ID) = 4096 0010 (plus VLAN ID) = 8192
  • 0011 (plus VLAN ID) = 12288 ...up to 1000 = 32768 (the default) ...up to 1111 = 61440

How the Switch Calculates the Final Value

When you assign a base priority to a switch, the hardware takes your base number and mathematically adds the VLAN ID to it to create a completely unique Bridge ID for that specific VLAN.

For example, if you configure your base priority to be 4096:

  • For VLAN 1: The absolute priority becomes (4096 + 1 = 4097).
  • For Slots in VLAN 10: The absolute priority becomes (4096 + 10 = 4106).

Because the switch uses those 12 bits for the VLAN ID, it is physically impossible for a standard hardware switch to accept a base priority like 2048, as that would require changing the 12th bit—which is strictly reserved for the VLAN architecture.

(Note: Software-based bridges, like the native Linux kernel network bridge, do not natively use the 12-bit Extended System ID modification for VLANs in the same way, which is why software bridges uniquely allow any arbitrary number from 0 to 65535, including 2048).
