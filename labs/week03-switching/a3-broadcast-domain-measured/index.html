W3·A3 — The broadcast domain, measured

Time: 25 min · Needs: four OL9 PCs + an Ethernet switch · GNS3 project: w03-a3-broadcast

The question: "broadcast domain" is defined in every textbook as "the set of devices that receive a broadcast". Fine — count them.

All four hosts must be OL9 PCs. VPCS has no sysctl and will not answer a broadcast ping, so a topology with VPCS in it silently under-counts.

Build it

PC1…PC4, all OL9 PCs, on one switch (the built-in Ethernet switch is fine here — it is scenery). 192.168.10.11….14/24, nmcli device set eth0 managed no on each.

Predict first

  1. PC1 sends one packet to 192.168.10.255. How many replies come back? _
  2. How many packets crossed the wire in total? _
  3. If two of the four hosts were switched off, would the switch still send it to their ports?

Do this

By default Linux ignores broadcast pings, which is itself worth a moment. Turn that off on the responders only:

# on PC2, PC3 and PC4 — not PC1
sysctl -w net.ipv4.icmp_echo_ignore_broadcasts=0

Start a capture on PC4's link. Then on PC1:

ping -b -c2 192.168.10.255

What just happened

  • Three hosts answered one packet. That set — the hosts that received it, whether or not they answered — is the broadcast domain, and it is exactly the set of ports the switch floods to.
  • ping reported the extra replies as DUP!. From the sender's point of view that is an anomaly; it is the only shape ping has for "more than one machine is answering", because the tool was designed for one-to-one.
  • The switch delivered it to every port regardless of whether anything was listening. A powered-off host still gets the frame sent at it; nothing about flooding depends on the far end existing.
  • The icmp_echo_ignore_broadcasts default is the good part: the switch delivered, each host decided. Layer 2 has no policy and no opinion; the hosts have both. That division is exactly what "layer" means, and it is the cleanest example of it this term.

Do this — count what a broadcast costs

Keep the capture running. On PC1:

ip neigh flush all
ping -c1 192.168.10.12

Look at PC4's capture.

What just happened

  • PC4's cable carried the ARP request, an ordinary broadcast that had nothing to do with PC4. PC4's kernel had to receive it, parse it, decide it was not the target, and discard it.
  • Every host in the domain pays that cost, for every broadcast, forever. With four hosts it is invisible. With four hundred on one segment it is a real load — and every one of them is doing it for every ARP, every DHCP discover, and every piece of discovery chatter on the network.
  • That is the argument for splitting a broadcast domain, and A4 is how it is done.
