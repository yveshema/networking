W2·A2 — One box, two devices ★

Time: 50 min · Needs: one OL9 Lab Node with 4 adapters, 4 VPCS · GNS3 project: w02-a2-one-box

The question: what makes a device a switch rather than a router? Buy the wrong answer and every later week gets harder.

Build it

  1. Drag out one OL9 Lab Node, name it BOX. Right-click → Configure → Network → Adapters = 4.
  2. Four VPCS, PC1…PC4, cabled to BOX's Ethernet0…Ethernet3.
  3. Start everything. Console into BOX as root.
# on BOX — before anything else
for i in eth0 eth1 eth2 eth3; do nmcli device set $i managed no; done
ip link show

On a QEMU node, GNS3's EthernetN is the guest's ethN, because the lab image boots with net.ifnames=0 biosdevname=0. On a marketplace appliance you would have to map them yourself.

Predict first

You have one physical box with four network ports.

  1. Can it be a switch? ☐ yes ☐ no
  2. Can it be a router? ☐ yes ☐ no
  3. Can it be both, one after the other, without rebooting or rewiring? ☐ yes ☐ no

Part 1 — Make it a switch

# on BOX
ip link add name br0 type bridge
ip link set br0 up

for i in eth0 eth1 eth2 eth3; do
    ip addr flush dev $i
    ip link set $i master br0
    ip link set $i up
done

bridge link
ip -d link show br0

All four PCs in one subnet, no gateway:

# PC1 / PC2 / PC3 / PC4
ip 192.168.10.11/24        # .12 / .13 / .14

From PC1: ping .12, .13, .14. All three work.

What just happened

  • br0 has no IP address, and that is correct. This node is not a host on the segment; it is the segment.
  • The four interfaces were stripped of addresses on purpose. A port carrying an IP is a router leg, not a bridge port — that distinction is the whole activity.
  • The PCs share one subnet and need no gateway, because as far as they are concerned they are all on one wire. BOX is invisible to them. Nothing in any PC's configuration mentions it.
  • What did the work: the bridge, reading layer 2 only, forwarding on MAC addresses it learned by watching. It never looked at an IP header.

Part 2 — Make the same box a router

Tear the switch down and build a router on the same hardware, same cables, same session:

# on BOX
ip link del br0                       # the switch is gone

ip addr add 192.168.1.1/24  dev eth0
ip addr add 192.168.2.1/24  dev eth1
ip addr add 192.168.3.1/24  dev eth2
ip addr add 192.168.4.1/24  dev eth3
for i in eth0 eth1 eth2 eth3; do ip link set $i up; done

sysctl -w net.ipv4.ip_forward=1

ip addr show
ip route show

Now re-address the PCs — four subnets, and each one needs a gateway:

# PC1
ip 192.168.1.10/24 192.168.1.1
# PC2
ip 192.168.2.10/24 192.168.2.1
# PC3
ip 192.168.3.10/24 192.168.3.1
# PC4
ip 192.168.4.10/24 192.168.4.1

From PC1: ping 192.168.2.10, then 192.168.3.10, then 192.168.4.10.

What just happened

  • The same box, the same cables, no reboot — and it is now a router. Nothing physical changed. What changed is which layer's addresses it reads and what it does with them.
  • ip route show filled itself in with four connected routes you never typed. Putting an address on an interface is an implicit claim that the subnet is out that port, and the kernel records it.
  • ip_forward=1 was the switch that made it a router at all. Without it, BOX has four addresses and forwards nothing — it is a host with four legs.
  • The PCs' configuration had to change too. They now need a gateway, because "not my subnet" is now a real category and somebody has to be asked. On the bridge, that category was empty.

Part 3 — Prove which layer each one used

# on PC1, after pinging PC2 across the router
show arp

Compare with the Part 1 result, where PC1 had pinged PC2 through the bridge.

What just happened

  • Through the bridge, PC1's ARP cache held PC2's MAC. PC1 addressed PC2 directly at layer 2; the bridge just moved the frame.
  • Through the router, PC1's ARP cache holds BOX's MAC, and PC2's does not appear at all. PC1 has never learned PC2's MAC and never will — it cannot, and does not need to.
  • So the frame PC1 sent was addressed to the router at layer 2 and to PC2 at layer 3, at the same time, in the same frame. The router rewrote the layer-2 addressing and left the layer-3 addressing alone.
  • That single observation is the most load-bearing fact in weeks 3, 4 and 5. Write it down properly.

If it went wrong

Symptom Cause Fix
Only eth0 exists adapters not set right-click → Configure → Network → Adapters = 4, then restart the node
Addresses vanish after seconds NetworkManager nmcli device set ethN managed no on all four, first
Bridge built, pings fail br_netfilter handing bridged frames to iptables sysctl -w net.bridge.bridge-nf-call-iptables=0
Router built, pings fail forwarding off, or PCs have no gateway sysctl net.ipv4.ip_forward; show ip on each PC and check the gateway column
Router pings fail only between some pairs firewalld systemctl stop firewalld for this activity
ip link del br0 refuses typo in the name ip link show type bridge to find it

Sidebar — the nmcli form

Your course persists interfaces with nmcli. Same kernel objects, written to disk:

# the bridge
nmcli con add type bridge ifname br0 con-name br0 ipv4.method disabled ipv6.method disabled
nmcli con add type bridge-slave ifname eth0 master br0
nmcli con up br0

# the router leg
nmcli con add type ethernet ifname eth0 con-name eth0 ipv4.method manual \
      ipv4.addresses 192.168.1.1/24
nmcli con up eth0

The ip forms above are for exploring, because they vanish on reboot and let you undo a mistake by restarting the node. Use nmcli when you want it to survive — which is what the project expects.
