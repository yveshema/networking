OSPF

Time: 60 min

Needs: w09-a1-dhcp project from the previous module; two additional OL9 Router nodes (R21,R3), two additional Ethernet Switch nodes (SW3, SW4), two additional VPCS nodes (PC4, PC5)

GNS3 project: w09-a1-dhcp (continue in it)

Info

Times listed are approximate and provided as timing guidelines only. Take as much time as you need to complete the activity.

Topology

This topology has four distinct segments connected by three routers.

  • LAN1: 192.168.10.0/28 (R1, DHCP-SRV, PC1, PC2)
  • LAN2: 172.16.10.0/28 (R1, PC3)
  • LAN3: 198.51.100.0/28 (R2, PC4)
  • LAN4: 203.0.113.0/28 (R3, PC5)

The routers are connected by direct, point-to-point links.

The cabling works as follows:

  • Run a cable between R1.eth2 and R2.eth0
  • Run a cable between R1.eth3 and R3.eth0
  • Run a cable between R2.eth1 and R3.eth1
  • Attach R2.eth2 and PC4 to SW3
  • Attach R3.eth2 and PC5 to SW4

Do this — configure the routers

Start by enabling IP forwarding on all three routers and assigning the addresses.

On R1 (IP forwarding should already be enable; verify before continuing): 

for i in eth2 eth3;do
    nmcli con add type ethernet ifname $i con-name $i
done

nmcli con mod eth2 ipv4.method manual ipv4.addresses 10.0.12.0/31
nmcli con mod eth3 ipv4.method manual ipv4.addresses 10.0.13.0/31

for i in eth2 eth3;do
    nmcli on up $i
done

On R2: 

echo "net.ipv4.ip_forward = 1" | tee /etc/sysctl.d/99-ip-forwarding.conf > /dev/null
sysctl --system

for i in eth0 eth1 eth2;do
    nmcli con add type ethernet ifname $i con-name $i
done

nmcli con mod eth0 ipv4.method manual ipv4.addresses 10.0.12.1/31
nmcli con mod eth1 ipv4.method manual ipv4.addresses 10.0.23.0/31
nmcli con mod eth2 ipv4.method manual ipv4.addresses 198.51.100.1/28

for i in eth0 eth1 eth2;do
    nmcli con up $i
done

On R3: 

echo "net.ipv4.ip_forward = 1" | tee /etc/sysctl.d/99-ip-forwarding.conf > /dev/null
sysctl --system

for i in eth0 eth1 eth2;do
    nmcli con add type ethernet ifname $i con-name $i
done

nmcli con mod eth0 ipv4.method manual ipv4.addresses 10.0.13.1/31
nmcli con mod eth1 ipv4.method manual ipv4.addresses 10.0.23.1/31
nmcli con mod eth2 ipv4.method manual ipv4.addresses 203.0.113.1/28

for i in eth0 eth1 eth2;do
    nmcli con up $i
done

Configure OSPF

We'll use a package called bird to configure OSPF. The configuration lives at /etc/bird.conf

R1 configuration

Run: 

> /etc/bird.conf

This clears the file of any existing content.

Edit /etc/bird.conf and add the following: 

log syslog all;

router id 192.168.10.1;

protocol device {}

protocol kernel {
    ipv4 {
        export all;
    };
}

protocol ospf {
    area 0 {
        interface "eth0", "eth1" { stub; } ;
        interface "eth*";
    };
}

Validate the configuration, then enable and start the service:

bird -p

systemctl enable --now bird

systemctl is-active bird

R2 configuration

Run: 

> /etc/bird.conf

Edit /etc/bird.conf and add the following: 

log syslog all;

router id 198.51.100.1;

protocol device {}

protocol kernel {
    ipv4 {
        export all;
    };
}

protocol ospf {
    area 0 {
        interface "eth2" { stub; };
        interface "eth*";
    };
}

Validate the configuration, then enable and start the service:

bird -p

systemctl enable --now bird

systemctl is-active bird

R3 configuration

Run: 

> /etc/bird.conf

Edit /etc/bird.conf and add the following: 

log syslog all;

router id 203.0.113.1;

protocol device {}

protocol kernel {
    ipv4 {
        export all;
    };
}

protocol ospf {
    area 0 {
        interface "eth2" { stub; };
        interface "eth*";
    };
}

Validate the configuration, then enable and start the service:

bird -p

systemctl enable --now bird

systemctl is-active bird

Here is the configuration breakdown:

Setting What it means
router id this router's name inside the protocol — though written to look like an address, it is just an identifier
protocol device keeps BIRD's view of local interfaces up to date; without it nothing notices a link change
protocol kernel copies what OSPF learns into the kernel's routing table
area 0 defines the contours of this OSPF topology
stub this setting says advertise this network, but send hello packets into it — recommended for a LAN with no routers on it

Do this - examine the OSPF topology

Run this on all three routers: 

birdc show ospf topology

The output should be similar on all three routers. This means they have the same map of their surroundings.

birdc show ospf neighbors

birdc show ospf state

The output show everything learned through OSPF. This is a dynamic database, and it updates automatically whenever there is a link change.

To prove it, intentionally disable a link on one of the routers, then run the commands again:

ip link set dev eth2 down

Start a capture between R2 and R3. Within a short time, you start seeing hello packets. These are used for neighbor discovery and to establish relationships between the routers. Open one of the hello packets and examine it.

On R3, run: 

systemctl restart bird

In Wireshark, locate and expand one of the LS Update packets and examine its contents.

Do this — update DHCP server

Instead of assigning addresses manually, we take advantage of our existing DHCP server.

On DHCP-SRV, edit /etc/kea/kea-dhcp4.conf and add two more subnet declarations:

...
"subnet4": [
    ...
    {
        "id": 3,
        "comment": "LAN 3",
        "subnet": "198.51.100.0/28",
        "pools": [ { "pool": "198.51.100.2 - 198.51.100.6" } ],
        "option-data": [
            { "name": "routers", "data": "198.51.100.1" }
        ]
    },
    {
        "id": 4,
        "comment": "LAN 4",
        "subnet": "203.0.113.0/28",
        "pools": [ { "pool": "203.0.113.2 - 203.0.113.6" } ],
        "option-data": [
            { "name": "routers", "data": "203.0.113.1" }
        ]
    }

]
...

Restart the service: 

kea-dhcp4 -t /etc/kea/kea-dhcp4.conf

systemctl restart kea-dhcp4

On R2 and R3, edit the dhcrelay service and start it:

systemctl edit dhcrelay`

Add the following content:

[Service]
ExecStart=
ExecStart=/usr/sbin/dhcrelay -d -4 -id eth2 -iu eth0 -iu eth1 192.168.10.14

Then: 

systemctl enable --now dhcrelay

systemctl is-active dhcrelay

Start PC4 and PC5 and get addresses through DHCP: 

ip dhcp

Verify that you can ping the other networks:

ping 192.168.10.2 -c 1

ping 172.16.10.2 -c 1
