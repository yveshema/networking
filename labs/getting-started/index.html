Weekly activities

Activity-led replacements for lecture time. Every activity follows the same shape:

  1. Predict first — written, before anything runs. This is the part that does the teaching.
  2. Do this — commands, no explanation.
  3. What just happened — the explanation, after the observation. This is answer-key material.
  4. Record — what lands on the worksheet.
  5. If it went wrong — the three or four failures that actually occur.

Ordering lives in one place

Each week's README.md holds the arc and the ordered index. Activity filenames carry no week number — the a1-/a2- prefixes are position within the week, and position changes. Moving an activity between weeks is a mv plus one line in two README.md files.

Files in a week directory

File Audience Notes
README.md instructor the arc, the ordered index, what the week assumes
aN-*.md student one activity, self-contained, includes "What just happened"
worksheet.md student predict → observe → explain, no answers
instructor.md instructor timing, what goes wrong, what to say, the gaps
topologies/ both exported .gns3project files, made once by the instructor

Distribute aN-*.md + worksheet.md. Keep instructor.md.

The activity files deliberately contain their own answers. Students who read ahead to "What just happened" before predicting are cheating themselves, not the grade — the grade lives in the project. If you want a clean split, the worksheet is the graded surface and the activities are reference.

Prerequisites

Environment setup is not duplicated here. It lives in ../gns3-lab0-switching.md:

  • §0a–0c — dynamips, Wireshark, VPCS. Needed from week 1, day 1.
  • §C0 — the OL9 Lab Node appliance. Needed from week 1, day 3. Once per term.
  • §D0 — Open vSwitch. Only for week 3 extensions.
  • Appendix A — the GNS3 VM on Hyper-V, for Windows students.

Week 1's README.md schedules those installs against class time.

GNS3 project naming

  • Activities → one throwaway project each, named for the activity: w02-a1-hub-vs-switch. Delete them freely; nothing depends on them.
  • The running project → one GNS3 project named campus, created in week 3 and carried to the end of term, snapshotted at each milestone. See ../project/README.md.

Never build a milestone inside an activity project, and never build an activity inside campus.
